# 토스 프론트엔드가 코드를 볼 때 보는 기준

이력서 없이 리포지토리 링크로 지원받을 때 밝힌 기준. [공개]

## 보는 것

1. 코드 품질, 모듈화, 디렉토리 구조. 가장 중요함
   - 자주 바뀌는 코드를 고치기 쉽게 만들었는지
   - 재사용할 수 있는 모듈인지
   - 원하는 코드를 쉽게 찾을 수 있는 구조인지
2. TypeScript. 함수와 컴포넌트의 입출력 타입을 정확하고 엄격하게 표현했는지
3. 제품 완성도. 로딩을 오래 기다리게 하지 않는지, 화면이 끊기거나 어색하지 않은지
4. 협업 능력. PR과 커밋 단위, 커밋 메시지, 코드 컨벤션을 지키는지
5. README. 무엇을 구현하는 프로젝트인지 알 수 있는지

## 중요하게 보지 않는 것

- 새로운 기술이나 유행하는 패턴을 아는지. TanStack이나 FSD 사용 여부보다 코드에 담긴 고민을 봄

## Platform 포지션 이력서 가이드

- 경험을 나열하기보다 임팩트와 배운 점을 씀
- 기술적 의사결정과 트레이드오프를 구체적으로 씀
- 장애, 성능 이슈, 운영 경험에서 구조를 어떻게 바꿨는지 드러냄

## 이 레포에서 챙길 것

- 결정에는 이유를 남김. 예: PnP에서 pnpm 링커로 바꾼 이유는 `.yarnrc.yml`과 `02-tech-stack.md`에 기록함
- 커밋과 PR을 작게 나눔
- 스켈레톤, 멱등 결제, 실패 안내 문구처럼 사용자 경험을 챙긴 흔적을 코드로 남김
