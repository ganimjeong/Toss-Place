# 영수증 출력과 출력 실패 처리 회고

결제가 끝나면 영수증을 자동으로 출력하고, 실패하면 다시 출력할 수 있게 만든 작업.

## 한 줄 요약

결제와 출력은 실패의 무게가 다르다. 이미 끝난 결제를 출력 실패가 되돌리거나 막으면 안 된다.

## 1. 출력 실패를 어디서 처리할까

- 고민: 처음엔 결제 결과 다이얼로그 하나에 "출력 실패"까지 같이 보여주려 함
- 판단: 결제 실패와 출력 실패는 같이 일어나지 않고, 사장님이 할 행동도 다름. 결제 실패는 다른 카드로 다시 결제하고, 출력 실패는 용지를 넣고 다시 출력함. Frontend Fundamentals의 "같이 실행되지 않는 코드 분리하기"에 해당한다고 봄
- 결정: 출력은 `printReceiptWithRetry`로 분리함. 실패 사유별 문구를 보여주고 "다시 출력"과 "건너뛰기"를 둠

## 2. 다시 출력 흐름을 상태 없이 만들기

- 이슈: 재시도 다이얼로그를 열고 닫는 상태를 컴포넌트에 두면 결제 흐름 코드가 상태 분기로 흩어짐
- 해결: overlay-kit의 `overlay.openAsync<boolean>()`을 씀. 다이얼로그가 닫힐 때 고른 값을 Promise로 돌려받아서, 출력과 재시도를 반복문 하나로 위에서 아래로 읽히게 씀
- 배운 점: 사용자 응답을 기다리는 흐름은 상태보다 `await`로 표현하는 게 읽기 쉽다

## 3. 장바구니를 비우는 순서

- 이슈: 결제 성공 후 장바구니를 먼저 비우면 영수증에 담을 항목을 어디서 가져와야 할지 헷갈림. 클로저 안의 `cart.items`는 아직 예전 값이라 지금은 동작하지만, 우연에 기대는 코드였음
- 해결: 장바구니를 비우기 전에 `toReceipt`로 영수증을 먼저 만들어 둠. 순서를 코드와 주석으로 드러냄
- 배운 점: 우연히 맞게 동작하는 코드는 리팩터링 한 번에 깨진다. 의도한 순서는 명시한다

## 테스트

- 기기 동작은 `window.posBridge`에 mock을 넣어서 바꿈. 번들이 브릿지 인터페이스만 알기 때문에 Electron 없이 결제 흐름 전체를 테스트할 수 있었음
- 확인한 시나리오: 정상 출력, 용지 없음 후 다시 출력, 카드 거절 시 출력하지 않고 장바구니 유지
